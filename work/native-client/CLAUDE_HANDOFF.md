| File | Purpose |

## How the closure works

1. Every function in every cached object (`out/`, `work/2008-06/native-check-runs/`,
   6615 distinct objects, 42148 distinct bodies) is compared to original bodies with
   relocation-masked bytes (`roc.native_bulk.Targets`, `match.exact_match`).
2. Seed: body of 16+ bytes with exactly one identical original body.
3. Each relocation in a seeded body names the referenced symbol and gives the original
   address in that field. That is a vote `symbol -> address`.
4. Votes choose between byte-identical candidates and name functions no object defines.
   Repeat to a fixed point (6 rounds).
5. A symbol with evidence for two addresses is a conflict and gets no binding.

Time: 3m42s for everything; 13 s for 71 objects.

## Why it matters for the converter

- Owner detection from mined packet text is unreliable. Example: packet
  `DxUserInput::func_0046a440` is really
  `?GetFileVersionAsString@CVersionInfo@@QAE...`; packet `FormattedString::~FormattedString`
  at 00465b50 is really `?isAdSyndicator@@YA_NPBD@Z`.
- Joined with `native-transplant-gate.json`: 259 of the 574 blocked rows now have a
  real mangled name (189 no-real-header, 29 signature-unproven, 24 ambiguous-owner,
  13 provider-unproven, 4 dependency-abi). See `gate_join` in `identity-closure.json`.
- The mangled name gives owner, full signature, calling convention, constness and
  virtual/static kind. No guess needed. `declaration` in the queue is the undecorated form.
- `identity-closure.json` is a valid `native-bulk` evidence receipt (rows carry `symbol`
  and `address`). Pilot: 8 classes, 73 s, 181 methods reached `inactive_exact` with no
  hand-written evidence.

## Limits (do not overclaim)

- A binding is identity evidence only. Not layout, ABI, link or runtime proof.
- The header that produced a mangled name may itself be an analog; a wrong parameter
  type that mangles differently but compiles to the same bytes would bind a wrong name.
  More independent votes = stronger. `votes` is recorded per row.
- `native-bulk` documentation says byte equality alone never assigns identity. Seeds
  here are byte-unique 16+ byte bodies, rechecked by `native-bulk` reference and data
  audit. Owner must accept this relaxation before any provider selection.
- Conflicts include real duplicates (two zlib copies, two `operator new`, ICF-folded
  templates). They stay unbound.
