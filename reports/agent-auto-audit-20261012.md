## Product changes

Workers → Agent worker previews eligible areas from the local catalog. Ranking is
explicitly heuristic: verified same-shape donor opportunities, genuine stored
recipe sources, imports, ABI/allocation/constants, then other near-misses. It
also uses recorded verified area gains and parks an unchanged source/profile
after two zero-gain repair batches of the same coherent family/recipe. Counts are
opportunities, not promised wins. Unrelated shapes no longer share repair batches.

Starting a run refreshes server sources, checks local/server readiness, leases
explicit disjoint addresses and recompiles baselines. Every selected area gets
compiler-only donor/recipe reuse before any paid CLI batch. Normal code/data
verification decides all reuse; a shape or RTTI label never proves ownership.
Batch workers apply shared hypotheses. Individual mining is off by default,
available only as a final fallback. Source-free/low-score targets can start from genuine same-shape exact donors; other unsupported targets stay deferred.

Each worker owns candidate files under `work/agent-auto/<run>/...`, leaving the
canonical source tree and scores files to existing synchronization. `agent-check`
records source hash, compiler/flags, score, diff and compile failure for each
requested check, and saves the best source independently. The wrapper recompiles
that best source before submitting under its lease. Only verified server
improvements count as new gains. Expired/unavailable leases and CLI/compiler
failures do not count as model-quality losses. Per-area batches are serialized;
different areas run concurrently. Limits cap workers, targets and time, not dollars.

Both agent CLIs now stream through the managed logger, so parallel output carries
worker identity. Dashboard model selection is passed through for unattended runs.
Existing job queueing and immediate stop remain in charge of the whole process
tree; the new run does not start unrelated sessions or modify recipes globally.
Agent workers reuse the Workers chat terminal, tabs, loop filters and run history.
Individual CLI output and tool summaries remain visible in compact mode.

The Claude pilot `5b644e5f2a76` produced two server-verified partial gains to 99%
(`004a74c0`, `005c76b0`) from compiler-only reuse, zero new exacts, and zero errors.
Claude made no source edits. It correctly declined unsupported individual mining
on unrelated Instance-getset/Ogre-tree targets; that prompted coherent batching.
Its ABI/tree-type diagnostics are hypotheses requiring authentic declarations.
This pilot does not establish improved AI exact yield. No DeepSeek testing ran.

Shared attempts now live in the group server DB and replicate through existing
cluster transactions. Authenticated uploads are bounded/idempotent; server gain
confirmation requires its own source hash and score event. Other PCs receive
reviewed lessons, failures, bounded diff/error excerpts and cached workflow docs.
Local paths/credentials stay out of exported reports. New endpoints require an
updated server; an old running server leaves trials queued locally.

Essential docs are tracked or newly prepared for the main repo, explicitly
included in helper ZIPs, and cached from the server when absent. `work/`, `src/`,
`tools/` and `local/` are intentionally ignored. Portable findings export goes
to `local/findings/agent-memory/`; source/scratch dependencies are not magically
available on another PC. See `docs/workspace-layout.md` for safe organization.

## Remaining priorities

1. Run a paired fixed-manifest Auto evaluation (two workers, 24 targets), compare unique verified
   exacts/bytes and compiler/model time against the same fixed-manifest control.
   The small Claude pilot above validates reuse/submission, not AI exact yield.
2. Make vendor dependency revisions part of compile-error and object cache keys.
   Current `compile_text` caches by directive text before library expansion;
   changed headers can replay stale errors/objects. Restart processes and change
   evidence stamps for historical recipe repairs until full dependency tracking
   exists. Auto's area cohort changes on source/extent changes, not every header.
3. Promote temporary Ogre generators/fork bodies into portable recipes with
   provenance and frozen tests. Current `try.py` and `ogre_resume.py` depend on
   one Claude scratch path and generated local library files. Auto can reuse
   stored recipes available on this machine; it cannot recreate missing scratch
   dependencies by guessing layouts or writing into tools.
4. Extend exact donor discovery beyond the current analyzed shapes with an
   independently verified family index. Source-free same-shape targets already
   use genuine donor seeds; unsupported targets remain deferred.
5. Add paired evaluation and budget/account usage telemetry for coding CLIs.
   Claimed dollar savings or universal superiority require measurements.
