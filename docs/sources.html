Sources

Every source we compile to match functions in the clients, plus what we still need and cannot find. A function counts as matched only when source compiled with the client's exact compiler produces byte-identical machine code. These sources are where those bytes come from.

Hard limits

Functions that cannot be matched no matter what source we find.

LimitEffect
VMProtectThe later clients import vmprotectsdk32.dll and virtualize selected anti-tamper functions. Virtualized code is a VM bytecode blob, not real x86 — no C++ source reproduces its bytes, so those functions are permanently unmatchable. A small set (license / integrity checks), not the bulk.

Techniques (no external source)

MethodWhat it does
mass fingerprintingroc mass compiles every configured source recipe with matching old MSVC builds and flag grids, compares machine code byte-for-byte against every client, then re-analyzes and runs auto-matching.
cross-client copyEvery matched source is recompiled against every other client; byte-identical functions shared between clients (and duplicate functions inside one client) match for free. roc xcopy.
auto shapesTrivial compiler-stereotyped functions (thunks, forwarders, small accessors) matched from their assembly shape. roc auto.
AI workersA local code model drafts C++ for one function, compiles, diffs the assembly and retries — with a Rev.ng hint and the 2016 source for the class. roc worker.

Needed, but not found

Sources that would unlock more matches. If you have any of these, drop them in the Discord.

SourceWhy it would helpStatus
G3D 8.00 / 8.01 sourceThe 2010–2012 clients link G3D 8.x. The official source zips were deleted from SourceForge and never captured by the Wayback Machine or mirrored to GitHub. The 2016 leak has a partial copy (used), but a clean 8.00/8.01 tree would match more of the rendering code.missing
Client PDB / MAPSymbols for any client exe would give exact function boundaries and real names — a huge boost to the AI workers and to unit assignment. None exist: the RBXGS installers carry only WebService.pdb (the grid service, a different binary), and the only leaked Roblox PDB is from 2022 (wrong era).missing
Roblox's Ogre subclass source~950 Ogre::Rbx* functions per late client are Roblox's own Ogre subclasses (RbxSceneManager, RbxEntity, RbxCluster…). Ogre was dropped before the 2016 leak, so this source exists nowhere public.missing
Exact per-TU compiler flagsRoblox built different translation units with different optimisation flags. We sweep a grid, but the real per-file flags (from a build log or project files) would match the functions the grid misses.partial
More community decompilationsRBXGSdecomp covers Nov 2007. A matching decompilation of a later build (2009–2012) would directly supply RBX source for the newer clients, where the 2007 source has drifted.wanted
