# 2008 XTP coverage investigation

Read-only investigation, 2026-10-11. Counts below use the published local
`docs/data/2008-06.json` snapshot, not a fresh group-server export. Scope is
functions whose displayed unit contains `CXTP`, so this is a UI-label cohort,
not a definitive inventory of all XTP code in the executable.

## Findings

The local XTP 11.2.2 source tree contains 325 C++ files. Having library source
does not mean those files reproduce the client's machine code with the current
compiler, headers, defines and flags.

Across 330 displayed units, 4,627 functions occupy 792,224 bytes. Exactly 3,034
functions (65.6%) match, covering 334,331 bytes (42.2%). The average exact
function is 110 bytes; the average unresolved function is 287 bytes. Large
functions therefore disproportionately leave the byte-progress bars incomplete.
248 unresolved functions exceed 500 bytes.

Examples of exact byte coverage:

| Displayed unit | Exact functions / total | Exact bytes |
|---|---:|---:|
| CXTPReportControl | 123 / 158 | 53.1% |
| CXTPCommandBar | 64 / 137 | 21.8% |
| CXTPPaintManager | 48 / 77 | 30.2% |
| CXTPRibbonBar | 63 / 95 | 27.3% |
| CXTPPopupBar | 42 / 47 | 88.7% |

There are 1,352 partials and 241 zero-score functions. 612 partials score below
50%; 1,229 partials have library-path metadata. These paths establish candidate
provenance, not correct identification. For example, `006a41e0` appears under
`CXTPCommandBar`, but its 23% candidate names
`Source/CommandBars/XTPCustomizeMenusPage.cpp`. Its local source file contains
only five metadata-comment lines. The published source flag counts file
existence (`roc/progress.py`), so it also counts such metadata-only stubs.
The local file audit found 1,229 unresolved metadata-only files and 126
unresolved files containing non-comment text. Exact entries also include 2,362
metadata-only files; this storage form does not invalidate their verified scores.
The live local scores file agrees with the snapshot's exact count and byte total.

Unit membership itself is approximate. `roc/analyze.py:rtti_classes` identifies
virtual functions from RTTI; `assign_units` carries the last class label forward
to subsequent functions until they are more than 0x4000 bytes beyond that
labelled function. These labels are neither original translation units nor
guaranteed ownership of every enclosed function. A unit's remaining functions
may need source from other classes/files.

Two existing investigations establish concrete configuration obstacles:

- `re-pilot-20261010.md` reports a 2007/08 CWnd layout discrepancy: target
  CreateEx slot 24 versus slot 22 in the pinned library header. Shared release
  MFC retains AssertValid/Dump slots; the separate shared-MFC XTP recipes
  preserve this configuration. This is evidence for particular ABI-sensitive
  functions, not proof that all remaining XTP functions share this issue.
- `library-branch-loop-20261010.md` records verified improvements from the
  interaction of /GS and /EHsc on particular source/target pairs. It also
  records exhausted and unsuccessful configuration pilots; repeating a broad
  flag sweep without new evidence is unlikely to help.

## Recommended next experiment

Choose a small cohort of large unresolved functions with strong identification
evidence from exact neighbors, call targets and matching source control flow.
Check target MFC member offsets and virtual slots first, then replay the
appropriate existing shared/static-MFC recipe with pinned compiler and known
successful cookie/exception settings. Preserve previous negative cohorts.
Only byte/relocation/data equality establishes recovery. Low-score library
candidates and inferred unit labels should not determine method identity.

No recovery run, server submission, settings change or existing source edit was
performed during this investigation.

## Follow-up results (same day, recovery runs)

Scope: 2008-06 functions whose unit label contains `CXTP`. All gains below are
server-verified byte/relocation/data matches.

| Stage | 2008 CXTP funcs exact | Exact bytes |
|---|---:|---:|
| Investigation snapshot | 3,034 / 4,627 (65.6%) | 42.2% |
| Earlier session (shared MFC, `/Ob1`, CString calls, private headers) | 4,223 / 4,627 (91.3%) | 83.1% |
| This session | 4,546 / 4,614 (98.5%) | 97.9% |

295 of 330 labelled units are now complete. This session added 522 verified
functions: 321 from the library-build recipe, 123 from `GetLength`, 69 from
boundary corrections and 9 from the int3 fix (non-XTP 2008 code).

### Root causes, in order of impact

1. **Wrong translation-unit prelude (+321).** Codejock's own library build
   precompiles `Source/Common/XTPDLLExports.h`, not our one-line `StdAfx.h`.
   That header sets `WINVER`/`_WIN32_WINNT` 0x0400, `_WIN32_WINDOWS` 0x0410,
   `_WIN32_IE` 0x0500, `VC_EXTRALEAN`, and pulls in afxpriv/afxtempl/afxcview/
   shlobj. The SDK otherwise defaults to Vista (0x0600). Visible symptom:
   `cmp eax, 0x20a` (target) vs `0x20e` (`WM_MOUSELAST`). Recipe
   `xtp-11.2.2-lib` preincludes the header and defines `_LIB`.
   Flags: `/O2 /MD /GS /EHsc /Ob1`. `/GS-` won 0 of 1,078 exacts.
2. **Imported MFC string helpers (+123).** The client calls
   `CSimpleStringT::GetLength` (plus `IsEmpty` and `operator PCXSTR`, found
   earlier) out of line. Symptom: ours inlines `mov ecx,[str]; mov ecx,[ecx-0xc]`,
   target has `call dword ptr [imp]`. Recipe `xtp-11.2.2-lib-strlen` marks them
   `__declspec(noinline)` through the recipe's `noinline` list (`roc/libs.py`).
3. **Analyzer function boundaries (+69).** The analyzer split functions at
   spurious starts (e.g. `Animate` at `006b3a70`, 1,041 bytes, was cut into
   383 + 657 bytes) and cut `__catch$` funclets into 6-byte stubs. It also
   merged tiny following functions. A whole compiled function that matches the
   exe byte-for-byte proves its own extent. `roc/analyze.py` now reads proven
   extents from `work/<client>/bounds.json`. For 2008-06 that is 81 extents,
   all inside 0x6a0000-0x7a0000. A dry run showed no change outside them, and
   all 78 extents still counted as code re-verified exact. The pre-correction
   table is kept at
   `work/2008-06/functions.before-bounds-20261011.jsonl`.
4. **Trailing int3 scoring artifact.** The analyzer strips trailing `0xCC`
   from exe functions; compiled functions kept it, so byte-identical
   functions ending in a noreturn call scored 99. `match.coff_functions` now
   strips the same bytes (never inside a relocation).

### Remaining 68

- **51 in the app region (0x40xxxx-0x5exxxx).** RTTI unit propagation labels
  them `XItem<CXTP…>`, `CXTPCommandBarsSiteBase<CSecureHtmlView>`, etc. Their
  bytes are Roblox app code: no `/GS` cookie, `ebp` frames, boost
  `lock xadd`. Explicit XTP template instantiation does not reproduce them.
  They are not XTP library code.
- **17 well-formed XTP functions with no exact compile among all 325 files.**
  Examples: `LoadAlphaBitmap`, `LoadToolbar`, `FilterToolTipMessageHelper`,
  `CXTPReportInplaceEdit::OnChar`. Diffs show statement/branch differences
  rather than configuration, which suggests the shipped XTP differs slightly
  from 11.2.2. These need individual decompilation.

### Recipe for other libraries

1. **Find the vendor's own build prelude.** Look for a DLL-exports, StdAfx or
   config header in the source tree, and replay with it preincluded. Check
   version macros against constant diffs such as `WM_*`, struct `cbSize` and
   feature guards.
2. **Settle runtime linkage first.** Shared vs static CRT/MFC changes vtable
   slots and import calls.
3. **Sweep flags per file on a small cohort.** Drop variants that never win.
   One flag set usually explains everything.
4. **Look at imported-call vs inlined diffs.** When the target calls an
   import where ours inlines a header accessor, add that accessor to a
   recipe `noinline` list.
5. **After each configuration converges, locate every compiled function in
   the exe byte-for-byte.** Hits whose extents disagree with the analyzer
   are proven boundary fixes. Dry-run them, and never resize an exact
   function unless the new extent is itself exact.
6. **Restart every server process after changing `roc/libs.py`,
   `roc/match.py` or a client's `functions.jsonl`.** Verifiers load recipes
   and tables at start-up and will otherwise reject or misjudge
   submissions.

Tooling: `benchmarks/xtp_coverage_run.py --recipe NAME [--shard i/n]
[--tag SUFFIX] [--only paths.json] --server URL` replays every library file
with a recipe and submits server-verified exacts. Journals and logs live in
`work/xtp-2008-20261011/`.
