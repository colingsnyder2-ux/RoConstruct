## New matching method: separate x87 math mode from SSE2

The existing recipe paired `/fp:fast` with `/arch:SSE2`. These are independent
choices: floating-point reassociation can matter even when emitted arithmetic
uses the x87 stack. The near-exact `GFont::get2DStringBounds` at `007b6b30`
differs in multiplication order. Keeping the existing source and compiler,
adding only `/fp:fast` gives an independently compiled, server-verified 99→100.
`/fp:strict` gives 44; `/fp:precise` stays 99.

The successful configuration is:

```text
/O2 /GS- /EHsc /MD /fp:fast
```

It is now an additional `g3d-6.09` grid entry. This changes candidate search;
the exact-match acceptance rules remain unchanged. Other clients were not run.

The bounded follow-up compiles twelve distinct source files ranked by unresolved
G3D candidate provenance, plus `GFont.cpp`, with fast x87 math and both `/GS`
settings. Candidate provenance ranks files; it does not establish ownership.
Every compiled function is compared against unresolved 2008 code, and every hit
is independently checked before submission. No stored partial is replaced by a
worse candidate.
