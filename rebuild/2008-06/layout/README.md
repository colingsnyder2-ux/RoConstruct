# 2008-06 organized source layout (export)

This folder is generated by `work/native-client/layout/layout_pipeline.py`. It is not the working
tree: live native sources stay in `rebuild/2008-06/native-classes` and `native-headers`.

Each file is one live native file placed at its original 2007/08 path
(`client/app/gui/ArrowPanel.cpp`, `client/app/include/gui/ArrowPanel.h`, ...). Paths come from the
source paths recorded in the RBXGS `WebService.pdb` (same engine tree), with file-name case from
OpenRBX. Only one-to-one mappings with no open review flag are exported.

Files are tidied on the way out: recovery notes (target addresses, compiler-flag pins, proof and
donor remarks) move to `evidence.json`, keyed by file and original line. `// INFERRED:` lines and
ordinary comments stay. Nothing is deleted from the live tree.

Proof, per `.cpp`: compiled beside its live original with the same compiler and flags, the object
is identical (code, data, relocations, symbols; only the discardable `.debug$S` section, which
embeds the object path, is excluded). A tidied file that does not reproduce the object is published
verbatim instead. Tidied headers are token-identical to the original and contain no line-sensitive
macros. `receipt.json` lists every file with its status and why other files are held back.

Not here yet: files with no original path evidence (most recovery units), merged or split units,
and files with open case or identity review. This is not a source-only client and not a P5/P6 gate.
